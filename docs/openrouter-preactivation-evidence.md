**Reservation assumption to check against that data** (code, `src/openrouter.ts`): the bound per call is `(request bytes + 64) x priceIn + maxOutputTokens x priceOut` using the **owner-configured** prices (no default), `max_tokens` is pinned, and `max_price` is sent so the provider must refuse an endpoint above them. Safe only if (a) configured prices equal or exceed the real per-token prices of every endpoint `max_price` allows, (b) tokens in never exceed bytes (true for any tokenizer), (c) the model has no separate per-request, reasoning or cache fee outside `prompt`/`completion` (if it does, **activation stays blocked**: the bound would be too low), (d) `maxOutputTokens` is within the model's output limit. If any is unknown, leave activation blocked.

## Operator checklist (document only; none of it was run)
Everything below is for Rai at the host, in order. Replace `<state>` with the orbit service's state directory.
1. **Decide:** model id (pinned slug from the metadata above) and price settings; accept or change the 250 ms lock wait; accept the manual-recovery gate for unprovable lock owners; choose B8 continuity (key-side limit at minimum).
2. **Dashboard:** fund the account minimally; create a new key with a credit limit <= $150 (lower for the smoke test) and verify it. Note the key's lifetime and today's usage (both 0 for a new key).
3. **Install the credential outside chat:** as root, typed directly in the SSH session (not via `!`, not pasted into an agent): `install -m 0600` the key to `/etc/credstore/orbit.openrouter`. Agents never read it.
4. **Config** in `/opt/orbit/orbit.env`: `ORBIT_OPENROUTER_ENABLED=1`, `ORBIT_OPENROUTER_MODEL=<pinned id>`, `ORBIT_OPENROUTER_PRICE_IN_USD_PER_MTOK`, `ORBIT_OPENROUTER_PRICE_OUT_USD_PER_MTOK` (from the metadata, rounded up), `ORBIT_OPENROUTER_DAILY_CAP_USD=5`, `ORBIT_OPENROUTER_TOTAL_CAP_USD=150`, optional `..._MAX_OUTPUT_TOKENS`, `..._TIMEOUT_MS`.
5. **Provision the ledger** (service user): `printf '{"openingLifetimeUsd": 0, "openingTodayUsd": 0, "note": "new key, dashboard showed $0 on <date>"}' > <state>/openrouter-spend.provision`; restart ORBIT; `/status` must say "OpenRouter fallback armed" with the stated spend. For a loss or a restored/replaced state directory use the recovery procedure in `openrouter-ledger-integrity.md` with the dashboard's numbers rounded up.
6. **Rehearse before any paid call** (isolated; never the live ORBIT or production ledger): (a) `node --test test/spend-ledger-multiprocess.test.ts` in a clone on the host: real SIGKILL at each critical-section point on a temporary directory. (b) Real-systemd: `systemd-run --user --unit=orbit-ledger-rehearsal -p StateDirectory=orbit-rehearsal ...` (or a throwaway system unit with its own `StateDirectory`) running `node test/helpers/ledger-worker.ts` against that unit's own directory; `systemctl kill -s KILL` it mid-section, `systemctl restart`, confirm the next call recovers, a pid-namespace-isolated unit (`PrivateUsers`/`PrivatePIDs` if available) fails closed with `busy` and leaves the lock, and the manual step in the ledger doc clears it. Never point it at `/var/lib/orbit`. **Not done here: needs the real host.**
7. **Separately approved minimal paid smoke test** (needs Rai's explicit go and a stated budget, e.g. <= $0.10 key limit): force a ChatGPT usage limit with the fake provider first (no spend); then, only after approval, one short fallback turn. Check: reply labelled "FALLBACK, paid", model and reset provenance, `/status` spend equals the dashboard within the model's reported cost, a background job during the limit does not spend, cap refusal text, recovery to ChatGPT after the reset.
8. **Stop / rollback:** `ORBIT_OPENROUTER_ENABLED=0` and restart (primary untouched); delete `/etc/credstore/orbit.openrouter`; revoke the key in the dashboard. Keep `openrouter-spend.json` and `.marker`.
9. **Tooling gaps found (not bypassed):** no allowlisted way for an agent to read public provider metadata (`openrouter.ai` is not in the session allowlist); no scripted rehearsal runner (steps above are manual); no tool to delete the lock and guard files, so the manual recovery needs a person at the host; no independent-review trigger from inside this job.
