# OpenRouter fallback: activation checklist

Status: **not activated, not production-ready.** Everything below was tested only with fakes. Model choice and activation are Rai's decisions.
Approved parameters: ChatGPT primary, fallback only on typed usage/rate limits, $5/day (UTC), $150 total.

## Fixed in PR59 (each has a regression test in `test/openrouter-fallback.test.ts`)
- Mock replies were relabelled "live" when the fallback wrapper was on: the primary's own result now passes through untouched.
- Non-tool fallback replies now carry the labelled "(FALLBACK, paid: ...)" source.
- Background callers (thread compaction, rolling note, scheduled runs) pass `{ fallback: false }`: while ChatGPT is limited they fail with the limit and never spend OpenRouter.
- Caps above 10,000 USD make the fallback `unavailable` with a reason; a ledger that cannot be built no longer crashes startup (`main.ts` reports it as unavailable).
- A failing ledger write on an error path no longer hides the provider error, leaks a file path, or discards a billed answer (it is returned with an accounting note).
- A non-JSON `/key` body is reported without echoing it.

## Fixed in the follow-up change (regression tests at the end of `test/openrouter-fallback.test.ts`; 9 of them fail on the previous main)
- **Tool-using turns are opt-in for the paid fallback.** `step()` never spends OpenRouter unless called with `{ fallback: true }`; `runChat` passes it only when its caller sets `fallback: true`. Callers audited (`grep runChat|\.step(` over `src/`): only `server.ts` `/chat` and `thread-service.ts` (interactive owner chat) call `runChat`, and both opt in. Any new caller gets the limit as it is. `reply()` keeps its opt-out (`fallback: false`) and the three background callers still use it. Tests count requests on a fake provider: zero for default, `{}`, `false` and background paths.
- **Accounting diagnostics are structured data**: `Step.accounting` / `Reply.accounting` / `ProviderError.accounting` (string list). No parenthesis stripping or text concatenation. They are never added to model text or to any model request. Owner sees them on `/chat` (`reply.accounting`), on the stored thread message (`accounting`, masked, capped) and rendered in the page; a failed later round keeps earlier diagnostics in the error text.
- **A billed tool-call-only reply with empty text keeps its calls and reports a failed ledger settle**, as does a billed reply that is then refused (no text, over the call limit, cut off mid tool call).
- Provider error plus ledger error: both reported, no path or key in the text.
- Unchanged: confirmation gates for tools, `FALLBACK_TOOLS` allowlist, no new fallback permissions, disabled by default.

## Fixed in the response/status hardening change (`test/openrouter-hardening.test.ts`, 24 tests; fakes only, no network)
Run against the previous `src/` (same test file, `src/` stashed): 21 of the 24 fail (20 assert-fail; the stalled-body test hangs until killed, because nothing there stops a stalled body); the 3 that pass are guards that must keep passing (normal and tool-only responses, repeated status issuing zero provider requests, complete replies never marked incomplete).
- **PR63 review cleanup.** A later-round failure no longer edits `error.message`. `runChat` builds a new `ProviderError` (kind, reset time and code kept, original as `cause`) from the bare text and the merged, deduplicated accounting list; the owner-visible "Spend accounting" sentence is composed once by `ProviderError` itself. The same diagnostic in two rounds is named once. A non-provider error is wrapped (name and `cause` kept), never mutated. `fallback.ts` `augment()` takes its accounting explicitly from every caller (the SpendError branch passes none) and no longer inherits it from the primary's error. Tests cover `/chat`, the stored thread, and that no model request carries diagnostics. Error classification is unchanged.
- **B11 (F3) bounded reads.** Provider bodies are read as a stream and counted in bytes before anything is buffered or parsed: completions 1,000,000 bytes, error bodies 64,000, balance 32,000. Content-Length is only an early refusal (a false or absent one is ignored). One deadline covers request plus body. On a limit the stream is cancelled; a possibly billed request stays charged at its bound; no retry; the error carries no provider text. Tests: oversized streamed body, false and huge Content-Length, oversized error bodies (500 charged, 429 released), stalled body, balance oversized/stalled/non-2xx, normal and tool-only responses. **Not covered:** real network behaviour (only fakes), and the 1 MB bound is a judgement, not a verified provider maximum.
- **B12 (F6a, N7) read-only truthful status.** `SpendLedger.inspect()` reads and validates the ledger without creating, adopting orphans into or writing it; `status()` uses only that. Tests: repeated status calls leave an existing ledger byte for byte unchanged (orphaned reservation not adopted), create no file on a fresh install, issue zero provider requests including no balance request. "armed" appears only when the config is complete and the ledger read cleanly on that call; corrupt, invalid, deleted-after-write, or a billed call whose ledger write failed now show "NOT armed" (state "down" while ChatGPT is limited); an uncreated ledger shows "configured but not verified". The status text says the model, key and prices come from configuration and have not been verified with OpenRouter, and marks the balance STALE after 20 minutes. ORBIT creates a missing ledger once at startup (`src/main.ts`), the explicit initialisation path; a failure there is logged and shown as NOT armed. Existing test `balance: the OpenRouter key view ...` relied on status creating the ledger as a side effect and was changed to initialise it explicitly.
- **B14 (N9) incomplete replies.** `incomplete` is a structured list on `Step`, `Reply`, `ChatOutcome`, the `/chat` reply and the stored thread message (rendered as "Incomplete reply: ..."), separate from `text`, tool arguments and `accounting`. Set for: `finish_reason` `length`, `content_filter` or `error` with text; an unrecognised finish reason; ORBIT's own 32,000-character cut; tool calls without id or name (dropped, reported). `stop`, `tool_calls`, `function_call` and a missing reason add nothing. A reply that ended with `length`, `content_filter` or `error` and carries any tool call is refused and nothing runs (previously only `length`). Billing warnings are reported independently (tested together). **Decision recorded, not guessed:** the audit asks for "a visible cut off note"; this puts it beside the reply, not inside the text, because stored text is replayed to the model on later turns. If Rai wants it inside the text, that is a separate decision.

## Still open (reconciled against current code; B11, B12 and B14 are now implemented and tested with fakes only, the rest are unchanged)
Definitions are from `docs/reviews/openrouter-fallback-audit.md` (backlog IDs B6-B14); the audit's F/N findings map as shown.
- B6 key-side credit limit and documentation of cost components outside `max_price` (F4/N4). **Open, owner step**: the only hard cap is a key credit limit set in the dashboard. A single reported cost of any size is recorded in full; the cap can be exceeded by one call.
- B7 single-writer lock (F5). **Open.** Two processes sharing the ledger can corrupt it (fails closed, denial not bypass).
- B8 ledger anchoring (N5). **Open.** Deleting the ledger file resets spend to $0 until a key-side limit stops it.
- B9 disallowed-tool behaviour (N3) and `job_launch` card text. **Open.** A disallowed tool call fails the turn and the paid call is still charged.
- B10 price rehearsal. **Open**, blocked on verified public prices.
- B11 byte-counted streamed reading (F3). **Implemented, tested with fakes; still needs the independent reviews below.**
- B12 side-effect-free `status()` (F6a) and "armed" shown while the ledger failed (N7). **Implemented, tested with fakes.** Status reads the ledger file on each call, so it can only be as truthful as that file; B8 (a deleted ledger before this process ever wrote one looks like a first run) remains open.
- B14 truncated-reply marker. **Implemented for the OpenRouter fallback client only** (ChatGPT replies are unchanged); the wording and placement decision is recorded above.
Restart durability, concurrency inside one process, caps and UTC rollover have passing tests (fakes only).

## Gates before any paid use (all required)
1. **Two independent security reviews** of the fallback, ledger and tool allowlist: **not done**; this change has had none, and PR review plus mocks are not a substitute.
2. Owner configuration: pinned model id, verified prices, `ORBIT_OPENROUTER_ENABLED=1`; credential `orbit.openrouter` installed by Rai (typed into SSH, not via `!`). Agents never read it.
3. OpenRouter key credit limit at or below $150 set and verified in the dashboard (the only hard cap); account funded minimally.
4. Rai approves tool scope (incl. `job_launch`) and the data flow (conversation, memory, tool results leave the host).
5. Deployment by Rai's normal process (not done here); confirm `/status` shows "armed" with the right model and a sane ledger. "Armed" means complete configuration and a ledger that reads cleanly, not that OpenRouter verified the key, model or prices.
6. Smoke checks against a fake provider on the real host layout: forced limit is served and labelled; a background call during a limit does not spend; cap refusal message; startup with an oversized cap still boots.
7. Rollback drill: `ORBIT_OPENROUTER_ENABLED=0` + restart returns the untouched primary; confirm ledger file preserved.
8. Break-glass: how to disable fast (unset flag, remove credential, revoke key in dashboard), who does it, and how to repair a corrupt ledger (never reset automatically).
9. Single ORBIT process owns the state directory (no second writer).
